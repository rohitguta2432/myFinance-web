    - Export named function ThemeProvider that accepts React.ComponentProps<typeof NextThemesProvider> and returns <NextThemesProvider {...props}>{children}</NextThemesProvider>
    - This is a thin wrapper required because Next.js App Router server components cannot directly import client-only libraries

    - "use client" directive at top
    - Import useTheme from "next-themes" and useEffect, useState from "react"
    - Export interface AppPalette with fields: bg, s1, s2, s3, txt, txt2, mute, accent, brd, brd2, danger, warn (all string)
    - Export const DARK_PALETTE: AppPalette = { bg: "#080E12", s1: "#0C1319", s2: "#121A22", s3: "#1A242F", txt: "#F0F4F8", txt2: "#CBD5E1", mute: "#94A3B8", accent: "#10B981", brd: "rgba(255,255,255,0.05)", brd2: "rgba(255,255,255,0.10)", danger: "#F87171", warn: "#FB923C" }

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage → React state | Theme preference read from client storage, applied to DOM via next-themes |
| Client DOM → CSS cascade | next-themes mutates html class attribute; CSS responds |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Tampering | localStorage myfinancial_theme | accept | Value is display-preference only (dark/light/system); tampering only changes visual theme, no security impact. next-themes validates the value against allowed themes on read. |
| T-06-02 | Information Disclosure | next-themes FOUC script | accept | The blocking script reveals that localStorage is used for theme — this is cosmetic data, not PII. Standard pattern used by shadcn/ui and thousands of Next.js apps. |
| T-06-03 | Denial of Service | disableTransitionOnChange temporarily removes CSS transitions | accept | Brief transition disable during theme switch (< 1 frame) is by design; not exploitable. |
</threat_model>
